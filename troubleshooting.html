Symptoms

Any of these usually means one of two things: Wacom's driver no longer supports your tablet, or it no longer works on your version of macOS.

  • The tablet's light is on and the pen moves the cursor, but Wacom Center displays "No device connected."
  • Wacom Center shows the tablet as connected and a pen icon appears on contact, but moving the pen does nothing — no cursor movement, no error message.
  • Wacom's installer says "Supported tablet not found."
  • Wacom Center shows "The tablet driver is not responding."
  • Wacom Center opens but the tablet panel is blank or crashes immediately.
  • An older driver worked, but reinstalling it after a macOS upgrade gives you no connection.
  • A newer Wacom driver pops up saying the tablet is no longer supported.
  • The cursor responds, but pressure works intermittently or not at all.
  • Everything worked until a macOS upgrade, and your tablet is not among the removed models. See Newer macOS than the driver knows.

Affected hardware

Wacom removes older models from its supported device list with each major driver release. Families it removed on macOS 14 (Sonoma), 15 (Sequoia), and 26 (Tahoe) include:

  • Intuos 1–3 — GD, XD, and PTZ series
  • Intuos 4 — PTK-440, PTK-640, PTK-840, PTK-1240
  • Intuos 5 — PTH-450, PTH-650, PTH-850
  • Intuos Pro Gen 1 — PTH-451, PTH-651, PTH-851 (K1 editions)
  • Bamboo and consumer Intuos — CTE, CTL, and CTH series (CTL-480, CTH-480, and similar)
  • Some older Cintiq pen displays

Intuos Pro Gen 2 (PTH-460, PTH-660, PTH-860) and Gen 3 (PTK-470, PTK-670, PTK-870) still have official support. For current compatibility, check the "compatible products" link inside a release's notes on Wacom's driver download page before installing.

Wacom announced one round of these retirements in a 2022 driver support bulletin, which names the affected families and the last driver version supporting each. Worth reading if your tablet is from that era — many owners never saw it. It was a one-time notice, though, not a running list. Wacom has retired later models without any announcement, which is why a tablet usually just stops working one day.

Newer macOS than the driver knows

Wacom's driver checks macOS against a list of versions built into it, and refuses to start on anything newer. Components report an undefined OS version and never initialize, so Wacom Center shows "The tablet driver is not responding" even with permissions granted. Your tablet is fine — the macOS version is the constraint, so check this first if your hardware is not in the Affected hardware list.

Each download on Wacom's driver page lists its supported range. Driver 6.4.14-2 (September 2026) covers macOS 13–15, 26 and 27, so a supported tablet that died on the macOS 27 upgrade should work again once you install it.

When Wacom has not yet caught up to a new macOS, you can stay on your previous release or switch to a driver that skips the version check. Patches to the installed Wacom binaries circulate too, but they modify signed system components and the next driver update overwrites them, so this page does not recommend them. For the underlying cause, see this independent root-cause analysis.

MockTab runs no such check. It reads the tablet through the macOS HID subsystem directly, requires macOS 13 or later, and sets no upper bound. It runs normally on the released macOS 27 in extended daily use.

Staying on Wacom's driver

If your model still appears in Wacom's supported device list, reinstalling an older driver sometimes restores connectivity. Wacom publishes previous releases on its support site, noting which hardware each version covers. Back up your pen and ExpressKey settings in Wacom Center before uninstalling — the process erases your configuration.

Important — Wacom's official guidance
Run a clean uninstall before installing another driver version. Use the Wacom Tablet Utility inside the driver package rather than deleting the application folder — most driver files live outside /Applications, and a drag-to-trash misses them. Wacom's standalone Wacom File Utility removes more. A full uninstall may need a reboot.
macOS Ventura 13 and later — Background access
On macOS 13 (Ventura) and later, you must explicitly allow the Wacom driver to run in the background. After installing, go to System Settings → General → Login Items → Allow in the Background, toggle Wacom on, and reboot. Skip this and you get the "tablet driver is not responding" error even when every other permission looks correct.
Missed the permission prompts?
Permission prompts fire the first time the driver exercises each protected capability. If they never appeared, uninstall and reinstall the driver to trigger them again.

Patched legacy Wacom drivers

For owners of discontinued Bamboo, Graphire, Intuos 1/2/3, and 1st-gen Cintiq tablets on macOS 10.15 Catalina through 12 Monterey, community member thenickdude maintains patched versions of Wacom's legacy drivers that fix the segfaults, preference-pane crashes, and installer failures Catalina introduced. The wacom-driver-fix repository has download links, the supported models per driver version, and permission-reset instructions.

These patches target that older OS window and do nothing on macOS 13 Ventura or later. If Wacom removed your model from the supported list, no version of the current driver will recognize it either. Both cases point the same way: MockTab or the outside tools below.

macOS permission setup

macOS security settings can block a correctly installed driver. Grant the Wacom driver these in System Settings → Privacy & Security:

Permission What to enable What breaks without it
Accessibility com.wacom.IOManager Pen input shows no response; security error appears
Input Monitoring WacomTabletDriver, WacomTouchDriver Tablet not detected; cursor doesn't move
Login Items → Allow in Background Wacom (toggle on) "Tablet driver is not responding" on Ventura 13+

Resetting stuck permissions

After a major macOS upgrade, the OS can lose track of permissions you already granted, even though the toggle still looks enabled. Remove each entry and add it back:

  1. Disconnect the tablet.
  2. Open System Settings → Privacy & Security → Accessibility. Select com.wacom.IOManager and click – to remove it.
  3. Repeat in Input Monitoring for WacomTabletDriver and WacomTouchDriver.
  4. Restart the Mac.
  5. After rebooting, manually add the entries back using the + button. The driver files live at:
    • /Library/PrivilegedHelperTools/com.wacom.IOManager.app → Accessibility
    • /Applications/Wacom Tablet/.Tablet/WacomTabletDriver → Input Monitoring
    • /Applications/Wacom Tablet/.Tablet/WacomTouchDriver → Input Monitoring

    Press Command+Shift+. in Finder to reveal hidden folders like .Tablet.

  6. Reconnect the tablet and test.

System maintenance tools

System-cleaning utilities can silently delete Wacom background services and preference files. If the driver stops working right after you run one, do a clean uninstall with the Wacom Tablet Utility and reinstall. Wacom has a guide for CleanMyMac interference on its support site.

Giving MockTab a try

MockTab talks directly to the macOS Human Interface Device (HID) subsystem. It needs no Wacom Center, no com.wacom.IOManager, and no background services.

1. Check hardware compatibility

Find your model on the Hardware page. Confirmed entries run on real hardware. Entries built from protocol references are reasonably reliable, but details like express key counts, touch behavior, and the LED ring may still need validation. File an issue if something doesn't match.

2. Remove Wacom's driver

Two tablet drivers will fight over the same HID device and produce erratic input, so MockTab warns you when it spots a competitor. Remove Wacom's with its uninstall utility or the standalone Wacom File Utility — deleting the app leaves service files behind — then restart. If you can't fully remove it, App Tamer or LaunchControl can suspend the Wacom background process instead.

3. Install MockTab

Download the latest disk image from Releases, open it, and drag MockTab to Applications. Launch it from there — macOS grants permissions only to an app running from its final location.

4. Grant permissions

MockTab needs Accessibility and Input Monitoring. The Configuration page walks through both. If a toggle doesn't take effect, remove MockTab from the privacy pane and add it again. Moving or reinstalling MockTab can invalidate an earlier permission.

Common post-install issues

Pen moves the cursor but pressure doesn't work

Pen pressure needs the Accessibility permission. Open System Settings → Privacy & Security → Accessibility, check that MockTab is listed and toggled on, then quit and relaunch it. If the toggle is already on, remove and re-add it.

Also check
Photoshop, Krita, Clip Studio Paint, and many other creative apps have their own pressure settings, separate from the driver. If pressure works in one app but not another, look in that app's brush or stylus settings.

Conflict warning in the Devices pane

MockTab posts a notice when another tablet driver is running at the same time. Quit or suspend it, then replug the tablet. The Devices pane updates once the conflict clears.

Tablet not showing up

An empty Devices pane after connecting usually means the device isn't in MockTab's registry yet. Choose Help › Collect Device Data… to record what the tablet sends into a single zip file. Attach it to a GitHub issue or send it by email from the same sheet, so we can try to add the device.

Bluetooth not connecting

The Intuos Pro gen 2 (PTH-460, PTH-660, PTH-860) uses Bluetooth Classic and needs a specific pairing sequence. The Intuos Pro gen 3 (PTK-470, PTK-670, PTK-870) uses Bluetooth LE and pairs normally. See the Bluetooth pairing section of the Configuration page.

Some websites or Calendar views won't scroll

Some websites, and Calendar's Month and Year views, ignore scrolling that coasts with momentum. Turn off Momentum Scrolling in the Touch pane for two-finger scrolling and in Pen Feel for Pan View. It's off by default in new installs.

Outside tools to try

If neither Wacom's driver nor MockTab solves it, two well-established tools cover a broad range of older hardware.

Connect my tablet Paid · App Store

A Mac app that walks you through driver and permission setup for legacy Wacom hardware. Current versions cover Tahoe, Sequoia, Sonoma, and back to El Capitan. Supports Bamboo, Graphire, Intuos 1–5, Intuos Pro, and many Cintiq models, essentially every Wacom tablet not still on the official driver.

wptrnpt.co.uk →

OpenTabletDriver Open source Free

A cross-platform (Windows, Linux, macOS), low-latency, user-mode tablet driver. Recent releases added pressure and tilt on macOS, along with pad-wheel support and full range output on all axes. Supports Intel and Apple Silicon Macs. Uninstall the Wacom driver first. Check the supported tablet list by model number before installing.

opentabletdriver.net →

Situation Recommended path
Model still on Wacom's supported list but driver won't load Fix permissions per the macOS permission setup section; reinstall the Wacom driver

Installing OpenTabletDriver on macOS

  1. Uninstall the Wacom driver completely using the Wacom Tablet Utility and restart.
  2. Download the latest release from opentabletdriver.net — choose osx-x64 for Intel or osx-arm64 for Apple Silicon.
  3. Extract the archive and drag OpenTabletDriver.app to your Applications folder.
  4. Launch it from Applications (not from the download location).
  5. Grant Accessibility and Input Monitoring permissions when prompted.
  6. Confirm your tablet appears in the Tablets list. If it does not, check the compatibility table by model number and consult the OTD FAQ.
Note on macOS 26 (Tahoe) permission bug
Some macOS 26 releases have a bug that keeps certain permission toggles from appearing in the Privacy & Security pane. If you are on 26 and a toggle is missing, follow every prompt carefully and check a current version of Connect my tablet for workarounds.
